## 1a. mvp3 Phase 7 (P7.7): found and fixed

**Found.** Phase 7 ran the three test videos end to end on the VM (`./start.sh --mode vm`, agent on port 8001, mvp3 database, `mvp3/` R2 folder): batch, suggestions, accept, Regenerate, remove by delete and by move, reject, manual merge, storage isolation, the features carried over from main, and a visual pass at 1440px and 390px. Acceptance items 1 to 9 passed after one blocking failure, fixed in the first row below. The fix plan took the remaining findings (40 items and 3 gaps against the accepted mockups): two suspicions were wrong (the slow banner was serial database reads, not thumbnail signing; the edit-mode "maximum of 0" was the browser default), item 36 was still leaking signed URLs, and item 39 (two parallel VLM calls on one GPU take about 75 s) is expected.

**Audit.** A full desktop (1440px) audit of `mvp3` then drove the console against the VM agent: 11 analyses, 14 builds, edits, official changes, a merge, removals, deletions and chat, and it left the database empty. It found 11 failures. The two high ones were that files of one batch never joined each other (a batch-mate had no report, so the judge scored it 0.0) and that multi-camera chat citations carry no camera. The medium ones were pending suggestions lost on every automatic join, a camera link that errored the report page, and "Awaiting your decision" on a file with no match. The rest were stale copy, an edit-mode overlap, an empty upload failure reason, the duplicate-name rule and an orphan upload object. Every unit except chat, the threshold and the orphan object is merged below.

**Fixed.** Every row is a PR merged into `mvp3`.
