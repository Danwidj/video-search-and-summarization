6. **Open: the agent unit tests cannot be set up with `uv sync` off NVIDIA's network.** The embedding-key test failures were fixed in #212 (2026-10-25). Run locally: `tests/unit_test/api/test_incident_search.py` passes (45) with `EVIDENCE_EMBEDDING_API_KEY` or `NVIDIA_API_KEY` set to a dummy value, and with the conftest from before #212 the 11 failures (`TestSearchRouteEndToEnd`, `TestCriticDelaySpacing`) reproduce, so #212 is the fix. Running the agent tests locally needs a workaround, because `uv sync --group dev` stops on two infrastructure problems: it re-resolves `uv.lock` (the lock is stale: it has no `supabase`) and so fetches the `eval` group's `nvdataset` from `urm.nvidia.com`, which does not resolve off NVIDIA's network; and with `--frozen`, `pycairo` needs a C compiler and the cairo headers (`services/agent/AGENTS.md`). The workaround, from `services/agent`: `uv venv --python 3.13 <venv outside the repo>`, then `uv export --frozen --group dev --no-hashes --no-emit-project | grep -v -E '^(pycairo|rlpycairo)==' > reqs.txt`, `uv pip install --python <venv>/bin/python --no-deps --index-strategy unsafe-best-match --extra-index-url https://download.pytorch.org/whl/cpu --extra-index-url https://pypi.nvidia.com/nvidia-nat/ -r reqs.txt`, `uv pip install --python <venv>/bin/python 'supabase~=2.0'` and `uv pip install --python <venv>/bin/python --no-deps -e .`; then `<venv>/bin/python -m pytest tests/unit_test/...`. Refreshing `uv.lock` (`uv lock`) needs NVIDIA's index and is still open.
